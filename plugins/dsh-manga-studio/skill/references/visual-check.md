# 生成した絵の検品

- いつ読むか: 画像生成モデルの出力（コマ・ページ）を受け取ったとき。写植のあと、公開・提出の前。
- いつ読まないか: ネームの段階（絵がまだ無い）。ネームの講評は `review-protocol.md`。

検品は、ネームと絵を突き合わせる作業で、絵の好き嫌いを言う場ではない。見るものはネームに書いてある。書いていないことで絵が良くなっていたら、それは残してよい（ネームを直す）。

## 1. 手順

1. ネームの台本（`name_render.py --md`）と、ネーム画像（`--html`）を横に置く。
2. ページを 1 枚ずつ、コマ番号の順に見る。下の表の上の層から順に見て、上の層で駄目なら下の層は見ない（読み順が崩れたページの、指の本数を数えても仕方がない）。
3. コマごとに「OK / 作り直し / 手で直す / keep（ネームと違うが良い）」と、理由を一句書く。作り直すのはそのコマだけ。ページ一括で生成した場合も、崩れたコマが 1〜2 個なら、コマ別生成で差し替えるほうが早い。
4. 作り直しの指示は、ネームの欄を直す形で書く（`pose` を変える、`box` で人物を離す、`expression` を弱める）。プロンプトだけ直して、ネームとずれたまま進まない。
5. 記録を `renders/epNNN/check.md` に残す。
6. 組んだページを縮小して並べ（スマホの画面くらい）、決めコマで目が止まるか、ページごとに密度の波があるかを見る。

画像を読めるモデルなら、検品を別のコンテキスト（サブエージェント）に任せられる。そのときは、ネームの台本とコマの画像だけを渡し、このファイルの §2 の表を基準にする。作者の意図や、生成で苦労した話は渡さない。

## 2. 見る順

| 層 | 見ること | よくある崩れ | 直し方 |
|---|---|---|---|
| 1. 読み順とコマ | コマ数、コマの並び（右→左、上→下）、どちらにも読める配置になっていないか、吹き出しの順 | 左から読む並び、段ごとに反転、コマの追加・欠落 | ページ一括をやめてコマ別に生成し合成する。page-prompt の読み順の行を先頭に |
| 2. 人物 | 人数、誰が誰か（顔・髪・服・小物）、左右（`pos`）、カメラが回り込むコマでの左右 | 左右の入れ替わり、指定外の人物、モブの消失、服の色の変化、別人の顔 | 人数と左右を絶対位置と相対位置で書く。キャラシートを毎回オリジナルから渡す。人物の箱を離す |
| 3. 台詞と話者 | 吹き出しのしっぽが話者を向いているか、右の人物が先に話しているか、画面外の声の扱い | しっぽの向き違い、吹き出しが話者から遠い | 写植で直す。in-image なら吹き出しを大きく、数を減らして再生成 |
| 4. 文字 | 誤字、脱字、縦書きか、行の順、句読点、擬音の字形 | 文字化け、横書きのナレーション、行の入れ替わり | 写植に切り替える（`--to lettering`）。擬音だけ画像に残す |
| 5. 演出 | ショット・アングルがネームどおりか、場面の頭で場所が分かるか、想定線、漫符の位置と意味、効果線の向き | 全部バストアップ、構図がランダム、漫符が別の人物に付く、集中線の中心がずれる | `shot` `angle` を強く書く。漫符は人物の `box` の近くへ。効果は後から描き足すほうが早いことが多い |
| 6. 体と物 | 指の本数、手と物の持ち方、関節、物の数と位置（前のコマとの連続） | 6 本指、持っていた物が消える、机の数が変わる | 胸から上で切る、手を隠す構図に変える、必要なら数枚生成して選ぶ（aipicks 2026-07） |
| 7. 背景と画風 | 同じ場所が同じに見えるか、時間帯と光、画風の統一。白黒の四値（線・ベタ・トーン・白）か。描き込みに強弱があるか（決めコマだけ密か） | 窓の位置が変わる、昼と夕方が混ざる、コマごとに線の太さが違う。灰色の厚塗り、髪のグラデーション、全コマに描き込んだ背景、全コマが一枚絵 | 場所の文面（`place_en`）と画風ブロックを固定。背景だけ先に生成して使い回す。灰の塗りは `tone_check.py`（1 ページ単位）で当たりを付け、目で厚塗りと確かめたら negative を強めて作り直すか二値化してトーンを貼り直す（`art-direction.md`） |
| 8. 余計なもの | 英字、透かし、署名風の落書き、指定外の文字 | 意味のない英字の看板、ロゴ | negative に書く。手で消す |

## 3. 公開・提出の前に

- [ ] 既存の作品・キャラクターに似すぎていないか、画像検索などで確かめた（文化庁チェックリスト 3-1-5。`formats.md` §3）
- [ ] プロンプトと修正の記録を残した（同 3-1-7）
- [ ] 投稿先・応募先の AI 利用の申告区分を確かめた（`formats.md` §2）
- [ ] `rating = "adult"` の作品では、登場人物が全員成人に見える描写になっている。幼く見える体格・服装・小物が混ざっていない
- [ ] 写植の文字を、ネームの台本と一字ずつ照らした（`--to lettering` の CSV と突き合わせる）

## 4. 書かないもの

- 「全体的にいい感じ」のような総評、点数
- 絵柄の好み（ネームと作品の画風ブロックに反していなければ、指摘しない）
- 生成していない絵、見ていないコマについての判定
