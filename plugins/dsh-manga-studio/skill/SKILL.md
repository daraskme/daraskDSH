# 日本語漫画の企画・ネーム・作画への受け渡し

LLM に漫画を作らせると、絵の前にネームで崩れる。どのページも同じ段組み、どの会話も顔の寄りの切り返し、感情は全部台詞で言い、場所は見せず、めくりは無視し、最後はナレーションで畳む。一コマずつは整っているのに、ページをめくる体験が平らになる。画像生成に進むと、さらに人物が入れ替わり、読み順が崩れ、文字が化ける。このスキルは、こうした問題に「描く前に決めること」「ネームを切るときの操作」「機械検査と別人の目」「画像生成への受け渡しの型」を割り当てる。

AI で作った漫画が「AI っぽい」と言われる原因の多くは、絵の上手下手ではなく、選ばないことにある。全コマを一枚絵のように均等に仕上げ、白黒なのに灰色で厚塗りし、どのコマにも背景を描き込み、どの感情も台詞で言う。漫画は、描くところと描かないところ、言うところと言わないところの差で読ませる。このスキルの操作は、その差を人（と LLM）が先に決めて、画像モデルに渡すためにある。

目指すのは一つの作風ではない。抑えた青年漫画も、記号だらけのギャグも、甘いラブコメも、成人向けも、その作品が読者に約束したものを、その作品の絵と間で描く。以下の操作は「偏りに気づいて選び直す」ためのもので、どれかの美学へ均すためのものではない。

以下、このスキルのベースディレクトリ（スキル読み込み時に表示されるパス）を `SKILL_DIR` と書く。

## 変わらない約束

1. 優先順位は、投稿先・応募先の規定 ＞ ユーザーの明示指示 ＞ 作品の契約（`manga.toml`・演出シート）＞ 既存のネームと原稿 ＞ このスキルの既定。ユーザーの絵と声は、こちらの好みより上にある。
2. ネームを書く前に読むのは、作品の契約と、その場面に要る参照だけ（`references/story.md`、`references/paneling.md`、`references/panel-layout.md`、`references/paneling-patterns.md` の該当パターン、必要なら `references/staging.md` `references/manpu.md`、場面の種類ごとの数字は `references/corpus-norms.md` §3）。AI 臭のカタログ（`references/ai-tells.md`）は書く前に読まない。避けたい型を見るとその型が出やすくなる。カタログは書いた後、lint・通読・レビューで気になった節だけ読む。
3. 数を言う表現は検算する。台詞の中の字数・個数・日付・年齢・曜日、ページ数とコマ数の内訳は、`name_lint.py`（C 群）か Python の計算で確かめる。頭の中で数えた数は信用しない。
4. ネームにはネームだけを置く。台詞にト書きや「（ここで間）」「※」を混ぜない（N05）。演出の意図は `beat` と配置に、メモは `note` に書く。
5. 自分で描いたものを自分で採点しない。機械で測れるものは scripts、読後の反応は別コンテキストの読者役、決めるのは作者。品質の点数はどこでも作らない。
6. 生成していない絵を、生成した・確認したと言わない。このスキルの成果物はネームとプロンプトで、絵の出来はモデルを回して検品するまで分からない。
7. 直しは良くなるとは限らない。直す前に守るコマを決め、直した後は前の版と比べ、負けたら戻す。
8. 連載では、決めたことをファイルに書く。会話にしかない決定は消える。LLM がネームで書き足した事実は proposed とし、作者が認めて初めて confirmed になる。
9. 実在の作家名・作品名・既存キャラクター名を、画風ブロックやプロンプトに入れない。既存の漫画のページを画像入力に使わない。参考作品から学ぶのは技法（コマ割り、漫符の型、間）で、絵や台詞そのものは写さない（`references/formats.md` §3）。
10. `rating = "adult"` の作品でも、登場人物は全員成人。幼く見える体格・服装・小物で描かせない。
11. ユーザーのネームや原稿を、頼まれていない深さまで書き換えない。

## モードを決める

| モード | こういうとき | 成果物 | 質問 |
|---|---|---|---|
| yonkoma | 4コマ 1 本〜数本、一場面だけのネーム | ネーム TOML と台本（会話に出す） | しない |
| oneshot | 読切（〜60 ページ）、短い 1 話完結、投稿用 | `notes.md` 1 枚＋ネーム TOML | 最大 1 往復 |
| serial | 連載、「第 N 話」「続き」、`manga.toml` がある | プロジェクト一式 | 初期化時に最大 3 問 |
| render | 「画像にして」「プロンプトを」「Krea の JSON に」 | 書き出し（krea / panels / page-prompt / lettering） | 文字の方針とモデルを 1 問（分かれば聞かない） |
| check | 生成した絵の検品 | 検品メモ（`references/visual-check.md`）。AI に検品させて直しを回すなら §5 | しない |
| letter | 絵ができたコマに、吹き出し・台詞・書き文字・効果線・漫符を載せる（写植・仕上げ） | 層の JSON と、組んだページ（`references/lettering-layers.md`） | しない |
| revise | 既存のネーム・漫画の講評や直し | 診断 → 承認された深さの直し | 深さを 1 問だけ |
| analyze | 参考ページ・参考作品の演出や漫符を分析して、作品の演出に取り込みたい | 5 系統の分析表 → 演出シートの案 | しない |
| consult | 相談、アイデア出し、「どう思う」 | 選択肢とトレードオフ（ネームは切らない） | してよい |

モードは依頼の中身で決める。`manga.toml` があるかどうかは、既存の契約と台帳を参照するかを決めるだけで、プロジェクトの中でも revise や render になる。

質問は「答えで骨格が変わり、後から安く直せないもの」（形式、ページ数、rating、結末の方向）に限る。それ以外は既定値で進め、依頼に無く結果を大きく左右する仮置きをしたときだけ、末尾に 1 行で告げる（例:「前提: 1 ページ目は左ページ（右綴じの奇数ページ）として割りました」）。

既定値: 横開き・右綴じ・1 ページ目は左ページ／1 ページのコマ数は通常 5〜6、見せ場 1〜3、最大 8（目安）／読切はストーリー 32 ページ前後、ギャグ 16 ページ前後（小学館新人コミック大賞の規定。応募先が違えばその要項）／4コマは 1 本 4 コマ・起承転結／縦読みは 1 話 50〜60 コマ（目安）／画像生成の文字は、吹き出しだけ描かせて後で写植（`blank`）。

## ネームを切るときの操作

### どの作品でも守ること

- **今回作る範囲と、読者が既に知っていることを決める。** 一本の 4 コマか、長い話の 1 話か、一場面か。読者の既知は、依頼が読了を前提にしている既出の話の中身だけ。設定資料はそれだけでは読者の既知にしない。範囲に要る人物の関係・役割は、要る時点までに絵か台詞で紙面に置く。
- **見せ場の一枚を先に決める。** この話でいちばん描きたい絵（告白の顔、必殺技、オチのコマ）を決め、そこにページと面積を使う。ネームはそこから逆算して割る（`references/story.md`）。
- **台詞とコマ割りを先に最後まで決める。** 絵（`visual`）は後から足す。途中のコマの絵を作り込むと、そこで止まる。
- **見開きで割る。** 右ページと左ページを一組で見る。左ページの最終コマで引き、めくった右ページの 1 コマ目で見せる（`turn`）。めくりの直前のページは、あえて均等に割って落差を作る（`references/paneling.md`）。
- **1 コマに 1 つの出来事。** `beat` が 2 文になるコマは、2 コマに割るか、片方を削る。
- **場面の頭で場所を見せる。** 引き（`long` / `extreme_long`）か、場所が分かる物のインサート。意図して伏せるなら、伏せたことを `note` に残す。
- **カメラを変える。** 同じショットを 3 コマ続けない。会話の切り返しは 3〜4 コマに 1 度、引きで位置関係に戻る。想定線を守る（右の人物はその場面の間ずっと右）。
- **感情は顔と体で。台詞は、口に出す理由のある言葉だけ。** 双方が知っていることを読者のために言わせない。泣き顔と涙の漫符と「悲しい」の台詞を重ねない。
- **吹き出しは右から、話者の近く（第一候補は頭の上）に。** 先に話す人物を右に置く（実際の漫画で 9 割がそう。`references/corpus-norms.md` §7）。画面外の声はしっぽを枠の外へ。1 行 12 字まで、1 コマ 2 個、1 ページ 12 個までが目安（`references/dialogue-and-lettering.md`）。長い台詞は 2 つに割り、後ろを下にずらして間にする。
- **漫符は感情が変わったコマに 1 つ。** 毎コマ付けると記号が何も言わなくなる（`references/manpu.md`）。
- **ページの割りは型から選んでよい。** よく使う型 30 と、珍しいが狙いのはっきりした型 12 を `scripts/layout_library.py` に保存してある。見せ場の位置・場面の種類・右ページか左ページかで選び、`show` の雛形を貼る。雛形には各コマの役割と `shot` の目安が入る（`references/layout-library.md`）。根拠が「強い」「中」の型は実際の漫画で広く使われている型、「実例ほぼなし」の型は構図の理屈で選ぶ型。プロは隣のページと同じ割りをほぼ使わない（1.4%）。大ゴマは顔の寄りより、人と人・人と場所を見せる。
- **場面の型に合うコマ割りを引く。** 告白、リアクション、アクション、恐怖、オチ。場面の種類が決まったら、`references/paneling-patterns.md` の冒頭の表で当たるパターンを 1〜2 個だけ開き、この場面の人物と物に置き換えて使う。同じパターンを続けて使わない。
- **依頼の条件を、出す前にネームと照らす。** ページ数、コマ数、登場人物、誰が誰に何をするか、順番、時期。書き上げてから一つずつ確かめる。
- **描き込みに強弱を付ける。** 決めコマ（`detail = "key"`）は 1 ページに 0〜1 個で、そこだけ人物を丁寧に、背景もきちんと描く（`background` を書けばそちらが優先）。ほかは `normal`（線とベタ、場所が分かる最低限の背景）と `light`（線を減らす、背景は白・トーン）。背景を描き込むのは場面の頭と決めコマだけ。全コマを同じ密度で仕上げると、一枚絵の並びになって漫画に見えない。`detail` と `background` は、ネームの最後の工程（台詞とコマ割りが決まった後、render の前）で各コマに付ける。欄の書き方は `references/name-format.md`、決め方は `references/art-direction.md` の §1（detail）と §3（背景）。
- **継ぎ足しや差し替えをしたら、頭から通して読む。** コマを足したページの後で、物の在りか、服、時間、誰がその場にいるかが食い違いやすい。

### 作風で分かれる操作

漫符の量、ナレーションの量、間の取り方、どこまで描き込むかは、作風で答えが逆になる。書く前に、依頼の語から決め、`manga.toml` の `[contract]` に書く。

- **記号の道**（ギャグ、ラブコメ、日常 4 コマ、子ども向け、成人向けの多く）: `manpu_level = "high"`。感情は漫符と表情の誇張で速く伝え、台詞は短く、テンポを優先する。オチの後に温かいまとめを足さない。
- **抑制の道**（青年ドラマ、シリアス、ホラー、ミステリー）: `manpu_level = "low"`。感情は間（無言のコマ、同じ構図の繰り返し）と描き込みの量で運ぶ。重い場面ほど情報量を増やし、軽い場面は減らす。
- 迷ったら、依頼が読後に約束している気分で決める。ジャンル契約は `references/genres.md`。場面ごとに切り替えてよい（ラブコメの山場は抑制の道、ホラーの日常パートは記号の道）。

## AI で作って、AI っぽくしない

AI に任せると平均が出る。平均とは、全コマ同じ密度、全員同じ美形、全部の感情を台詞で言う、全部のページを同じ数で割る、ということだ。人が決めるのは、その平均から外れる場所である。

1. **人が決める: 何を見せ、何を省くか。** 見せ場の一枚、ページで一番大きいコマ、決めコマ、背景を描くコマ、台詞を削って顔に任せるコマ。ネームの段階でファイルに書く（`beat` `detail` `background`）。
2. **AI に任せる: 決めたことの実行。** 台詞の言い換え案、コマごとのプロンプト、作画。任せるときは、決めたことを毎回同じ文面で渡す（画風ブロック、人物ブロック、`detail` と `background` の訳）。
3. **話の中身に合わせて割る。** 言葉の多い場面（会話・日常・ギャグ）はコマを小さく多く、言葉の少ない場面（悲しみ・恋愛・スポーツ）はコマを減らして大きく、動きの場面は台詞を擬音と効果線に置き換える。実際の漫画の数字は `references/corpus-norms.md` §3。
4. **白黒は線・ベタ・トーン・白の四つで。** 人物を厚塗りしない。髪は特徴が分かる程度で、黒髪はベタでよい。背景は、場所が分かる最低限と、話に要る物だけ（`references/art-direction.md`）。
5. **測れるものは測る。** ネームは `name_lint.py`（突出した大ゴマが無い P14、描き込みの配分 P15 を含む）、絵の灰の塗りは `tone_check.py`。数字が平均から外れていること自体は悪くない。外れた場所が、狙った場所かを確かめる。
6. **縮小して読む。** 組んだページをスマホくらいの大きさで並べ、決めコマで目が止まるか、密度に波があるかを見る。

## モード別の手順

### yonkoma
1. 起承転結の 4 コマで、何をずらして笑わせる（または和ませる）かを一言で決める。
2. `references/paneling-patterns.md` の 4コマの型を見る。オチの型（ずらし、天丼、無言オチ）を選ぶ。
3. ネーム TOML を書く（`format = "yonkoma"`。`assets/templates/yonkoma.toml` が見本）。保存先が無ければ作業ディレクトリに置く。
4. `name_lint.py` を 1 回。FAIL は確かめて直し、WARN は fix / keep を選ぶ。
5. `name_render.py --md - --reader` の台本を会話に出す（求められれば `--html` のネーム画像も）。既定は台本だけ。lint の結果や技法の説明は書かない。

### oneshot
1. `notes.md` 1 枚: ログライン、読者への約束、主人公の感情の変化、見せ場の一枚、ページ配分（`references/story.md`）、人物（外見の固定文面と声）、演出の 3 点（コマ数の傾向、漫符の量、ナレーションの量）。
2. 確認は最大 1 往復（ページ数・結末の方向・rating が決まらないときだけ）。
3. ネームは 4〜8 ページずつに分けて書き、その都度 lint とネーム画像で見開きを確かめる。1 本を一度に出さない。
4. 書き上げたら `review-protocol.md` で読者役 1 ＋編集役 1。直しは最大 2 周。
5. 作画に進むなら render へ。

### serial
`references/longform.md` に従う。新規なら `init_project.py` でプロジェクトを作る。1 話ごとの流れ:

```
- [ ] STATUS.md を読む
- [ ] build_context.py でコンテキストパックを作り、パックだけを読む
- [ ] plot/episodes/epNNN.md（場面の並び・引き・reader_should）
- [ ] name/epNNN.toml を数ページずつ。保存のたびに name_lint.py
- [ ] name_render.py で台本とネーム画像 → 通読
- [ ] レビュー（review-protocol.md）→ 直し
- [ ] canon を更新（事実は proposed で追記、要約は 1 行目「状態: proposed」）→ 作者の承認で confirmed
- [ ] decisions.md と STATUS.md を更新
```

### render
`references/image-generation.md` に従う。先に `references/art-direction.md` で、各コマの `detail` と `background`、画風ブロックを決める。生成の単位（コマ別 / ページ一括 / bbox で配置）と、文字の方針（`blank` / `in-image`）を決め、`name_export.py` で書き出す。Krea 2 の JSON/BBOX LoRA には `--to krea`（人物の `lora` 別名と `pose`、台詞の `speakers` が入る）、PH3DaraskMix の manga lora には `--to krea --layout-prefix ph3`。文字と線の演出を絵に描かせない作り方なら `--to anima`（絵のプロンプト）と `--to layers`（層の叩き台）を出す（`references/lettering-layers.md`）。書き出した後に「生成した」とは言わない。生成した絵が来たら check、その後 letter。

### check
`references/visual-check.md` の表を、上の層（読み順・人物）から順に見る。Pillow があれば `tone_check.py` で灰の塗りも測る。コマごとに OK / 作り直し / 手で直す / keep と理由。作り直しはネームの欄を直す形で指示する。画像を読めるモデルに検品させて直しを回すときは §5（落とすのは話を追えなくなる点だけ、回数に上限）。

### letter
`references/lettering-layers.md` に従う。各コマの絵を見てから、ネームの台詞・擬音・効果・漫符を層として置く。台詞はネームのとおり、吹き出しは顔と見せ場に重ねない、読む順に、しっぽは話者の口元へ。書き文字のスタイルは `references/sfx-styles.md` から場面で選ぶ。`typeset.py` で SVG、`page_compose.py` でページ、`make_cbz.py` で CBZ。

### revise
1. 直す深さを決める:（1）台詞と表記だけ（2）演出まで（カメラ・漫符・吹き出しの配置）（3）コマ割りと構成まで。依頼から分かればその範囲、分からなければ 1 問だけ聞く。
2. 既存のネームが TOML でなければ、まず TOML に起こす（中身は変えない）。`name_lint.py` と通読で診断し、気になった項目の節だけ `references/ai-tells.md` を読む。
3. 作者の台詞の声と、出来事の中身は残す。直したら前の版との差を、ページ-コマで示す。

### analyze
参考ページ・参考作品（ユーザーが渡した画像や、ユーザーの説明）から、描き込みの配分（`references/art-direction.md` §0 の表）と、`references/manpu.md` の「1 枚の分析テンプレート」（感情の記号／体から出る効果／動きと画面の効果／擬音の系統／文字の描き方）とコマ割りの型を表に起こす。結果は作品の演出シート（`style/directing.md`）の案にする。写すのは型と使いどころで、絵・台詞・固有の意匠は写さない。

### consult
ネームは切らない。選択肢は 3 案まで、それぞれのトレードオフを添える。材料は `references/story.md` `references/genres.md` `references/paneling-patterns.md`。ユーザーの反応を捏造しない。

## scripts

`tone_check.py` 以外は、すべて Python 3.11 以上の標準ライブラリのみ。例の `python` は、環境にある `python3`・`python`・`py` に読み替える。いずれも無ければ機械検査を飛ばし、ネームを台本の形（`references/name-format.md` の台本の見出し）で直接書き、その旨を本文の外に記録する。詳しい引数は各スクリプトの `--help`。

| スクリプト | 役割 |
|---|---|
| `python "SKILL_DIR/scripts/name_lint.py" name.toml [--stats] [--json] [--only EBPM]` | ネームの機械検査。構造（E）、表記（N）、数え上げ（C）、吹き出しと文字量（B）、コマ割りと演出（P）、漫符（M）、人物の一貫性（X）。FAIL は構造（型・範囲・ページ番号の重複を含む）・本文以外の混入・数え上げだけ、他は警報。構造の FAIL があると描画と書き出しは止まる |
| `layout_library.py list\|show ID\|preview OUT.html\|add ID ...` | コマ割りの型の保存庫。一覧、説明（目的・使う場面・コマごとの中身・根拠）と、各コマの役割と shot の目安つきの TOML の雛形、ネーム画像での見本、作者の型の追加 |
| `tone_check.py page.png ...` | 生成した白黒ページの灰の塗り（白・黒・中間・なめらかな灰の面）を測り、なめらかな灰の面が 0.005（実際の漫画の上位 5% の少し上）を超えるか、白が 48% 未満なら知らせる（目で確かめる場所の印）。見開きは `--spread` で左右別に。**Pillow が要る**（無ければ飛ばして目で見る） |
| `name_render.py name.toml --md 台本.md [--reader] / --html ネーム.html / --svg DIR` | 台本（読者用は設計情報を落とす）と、コマ割りの見えるネーム画像（右綴じの見開きで並べる） |
| `name_export.py name.toml --to krea\|panels\|page-prompt\|lettering\|sections --out ...` | 画像生成と写植への書き出し。krea は krea_layout_v1（絶対座標の JSON と正規化プロンプト、`--krea-repo` で外部の検査も。`--layout-prefix ph3` で PH3DaraskMix の manga lora 向けの ph3_layout_v1）。panels・page-prompt には `detail` と `background` の指示が英語で入る。sections は見出し区切りの文章（title・panelN のプロンプト・ページごとのセリフ・組み立てに渡らない文字の notes）。compose はページを組む道具に渡す画素の配置（JSON） |
| `name_export.py name.toml --to anima [--prefix …] / --to layers` | 絵と層を分ける作り方の書き出し。anima はコマごとの絵のプロンプト（文字と層で描く演出を外し、T5 512 トークンに収める）とネガティブ、layers はコマの縦横比と層の叩き台（`name_layers.py`） |
| `typeset.py panel layers.json --aspect A --out panel.svg / styles / sample OUT` | 写植・演出の層を SVG に（文字はパス、縦書きは HarfBuzz の字形）。書き文字 19 スタイル。**fonttools・uharfbuzz とフォント（`fetch_fonts.py`）が要る** |
| `page_compose.py name.toml --images DIR [--layers L] --out DIR [--png]` | ページを組む（絵をコマ枠に切り抜き、枠線、層）。PNG は rsvg-convert か Chrome があるとき |
| `make_cbz.py OUT.cbz p*.png --title 題名` | ページを CBZ に（右綴じ・白黒の ComicInfo.xml） |
| `fetch_fonts.py [--dest DIR]` | 写植のフォント（Google Fonts・SIL OFL）を取る |
| `name_convert.py name.json --out name.toml` | ネームの JSON と TOML の変換（LLM に JSON で書かせ、人が TOML で直す） |
| `init_project.py DIR` | 漫画プロジェクトの雛形 |
| `build_context.py --project DIR --episode N` | その話に要る情報だけを 1 枚に束ねる（confirmed の事実だけ） |

lint の読み方: lint は FAIL を含めて「確認する箇所」を示す検知器で、修正命令ではない。機械はコマの絵を見ていない（意図して場所を伏せた導入、わざと続けるアップの連打、作中の手紙に付けた句点）。抜粋だけで決めず、該当コマと前後のコマ、作品の契約を見てから、誤りと確かめたものだけ fix する。誤検出や意図した演出なら変えずに keep とし、理由を一句残す。判断がつかないものは「要確認」で残す。完了の条件は FAIL が 0 になることではなく、指摘をすべて確かめて処置したこと。閾値はすべて目安で、作品ごとには較正していない（`scripts/data/thresholds.json`。主なものは実際の漫画 6,741 ページと照合済み、`references/corpus-norms.md` §5）。作品の流儀で止めたい規則は `manga.toml` の `[lint]` に理由つきで書く。

配置の推定: ネーム画像と krea の書き出しにある人物・吹き出し・漫符の位置は、`manga_name.place_panel` の推定（叩き台）。読み順と左右は守るが、顔の位置までは知らない。重要なコマは `box` で固定する。

## レビューの委任

読者役・編集役・校閲役は、作者との会話履歴・親の要約・設計資料を引き継がない新しいコンテキスト（サブエージェント、または Codex CLI などの別系統モデル）に任せる。委任文はこの型だけにし、作者の意図や執筆中の会話を渡さない。

```
最初に SKILL_DIR/references/roles/reader.md を読み、その指示に従うこと。
対象: <name_render.py --reader で作った台本のパス>（とネーム画像の PNG）
（連載なら）前話までのあらすじ: <パス>
上記以外のプロジェクト内ファイルを読まないこと。
出力先: <reviews/ のパス>
```

読者役には点数も直しも「AI っぽいか」の判定も求めない。求めるのは、読みながらの反応（読み順に迷った、誰の台詞か迷った、めくって驚いた）、自分の言葉での再話、相対的に最も弱いページ。親はそれを話の筋の `reader_should` と突き合わせる。手順と外部モデルへの依頼の雛形は `references/review-protocol.md`。返ってきた指摘も同じ基準で裁き、外部だからという理由で優先しない。
