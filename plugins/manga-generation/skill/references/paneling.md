# コマ割りの原則（paneling）

- いつ読むか: ネーム（name TOML）のコマ割りを決めるとき。`name_lint.py` が P01・P02・P07・P08・P10・P12 を出したとき。ページ配分を見直すとき。
- いつ読まないか: 企画やプロットの段階（`story.md`）。台詞の推敲だけをするとき（`dialogue-and-lettering.md`）。場面ごとの具体的な型を探すときは先に `paneling-patterns.md` の表を引き、この原則は迷ったときに戻る。
- 数は目安である。出典のある数には出典を、無いものは「目安」と書いた。作品の演出シート（`style/directing.md`）と `manga.toml` の契約が、ここの既定より上にある。

## 1. 読み順

右綴じの日本の漫画は、**段を上から下へ、段の中を右から左へ**読む。吹き出しも同じ順で読まれる（https://www.clipstudio.net/oekaki/archives/149462 、https://shincomi.shogakukan.co.jp/training/006.html ）。

```
┌───────────────┬──────────┐
│       2       │    1     │   ← 1 段目: 右の 1 から左の 2 へ
├──────┬────────┴──────────┤
│  4   │         3         │   ← 2 段目
├──────┴───────────────────┤
│            5             │   ← 3 段目
└──────────────────────────┘
```

守ること:

- **どちらの順でも読める配置を作らない。** 上の図で 1 段目と 2 段目の縦の境目がそろっていると、読者は 1 → 3（縦）と 1 → 2（横）のどちらに進むか迷う。段の境目（横線）はページの端から端まで通し、縦の境目は段ごとにずらす。
- **間白（コマの隙間）は、左右の隣とは狭く、上下の段の間は広く。** 筆者の目安は、広い間白 8〜10mm、狭い間白 4〜6mm（https://www.clipstudio.net/oekaki/archives/149462 ）。逆にすると縦に読ませられるが、そのページだけの意図として使う。`manga_name.py` の配置計算はこの原則どおり、段の間（`GUTTER_Y`）を左右の間（`GUTTER_X`）より広く取る。
- **見開きの視線は逆 Z。** 右ページの右上から入り、左ページの左下で抜ける（https://note.com/comico_jp/n/nbfcfacb6a916 ）。見開きの最後（左ページの左下）に、次のページへ進ませる引きを置く（5 節）。
- **縦に積んだコマは、その列の中で上から下。** 段の中を縦に割った組（`column`）は、右の列の上 → 右の列の下 → 左の列、の順に読まれる。

```
┌──────────┬────────────┐
│          │     1      │
│    3     ├────────────┤   ← 右の列を縦に割った組（column）
│          │     2      │
└──────────┴────────────┘
```

- **縦読みは上から下への緩やかな S 字。** 視線が左右に振れても最後は画面の中央へ戻し、吹き出しは横に並べず上から下へずらす（https://note.com/comico_jp/n/nbfcfacb6a916 、https://mannavi.net/21297/ ）。

TOML では、**ファイルに書いたコマの順が、作者の意図する読み順**。配置（`tier` / `width` / `column` / `bbox`）から計算した読み順がそれと違うと、`name_lint.py` が **P02** を出す。P02 が出たら、配置を直すか、書く順を直す。どちらが正しいかは、そのページで読者に何を先に見せたいかで決める。

## 2. 1 ページのコマ数

| 場面 | コマ数（目安） | 出典 |
|---|---|---|
| 上限 | 8 | https://www.clipstudio.net/oekaki/archives/149462 |
| 初心者の基準 | 5 前後 | 同上 |
| 通常の展開 | 5〜6 | https://blog.copainter.ai/manga-koma-wari-guide/ （AI 企業の解説、信頼度は中） |
| 感情を見せる | 3〜4 | 同上 |
| 見せ場 | 1〜3 | 同上 |
| 見開き 1 つ | 8（1 ページ約 4） | 原作者の書式の例 https://iharadaisuke.hatenablog.com/entry/2015/11/18/160913 |

ジャンル別（少年誌・少女誌など）のコマ数の公的な数字は見つかっていない（未確認）。

- `name_lint.py` は、コマ数が `panels_min`〜`panels_max`（既定 3〜8）の外だと **P01** を出す。扉や見せ場の 1 枚絵のように意図して少ないページは、ページに `splash = true` を書くと P01 が止まる。
- **同じ大きさのコマばかり並べない**（https://www.clipstudio.net/oekaki/archives/149462 ）。全ページが 5 コマ均等なら、どのページにも山が無い。コマ数より先に「このページでいちばん大きく見せるコマはどれか」を決め、それに面積を配る。

## 3. コマの大きさと形は、時間と重みを決める

- **大ゴマ**: 読者の目が長く留まる。強く伝えたい情報や心情を置く。場面転換にすぎないコマは小さくてよい（https://www.clipstudio.net/oekaki/archives/149462 ）。大小の比は約 3:1、主役のコマは他の約 2 倍という実践談がある（https://aipicks.jp/mag/ai-manga-pro-quality-tips 、目安）。
- **小ゴマの連打**: 時間を細かく刻む。リアクション、手元の動作、カウントダウン。連打のあとに大ゴマを置くと、落差で大ゴマが効く（`paneling-patterns.md` の 07・08）。
- **横長のコマ**: 時間の流れ、横の移動、広さ、沈黙。間を取りたい無言のコマは横長にすると、読者は「長い時間」と受け取る（目安）。
- **縦長のコマ**: 高さ、落下、見上げる・見下ろす、立ち姿の全身。塔や崖、跳躍の頂点（目安）。
- **コマの数＝読む時間ではない。** 文字の多いコマは小さくても時間がかかる。大ゴマに長い台詞を詰めると、絵より文字が先に目に入る。見せ場の絵の横に台詞をまとめて置かない（https://mannavi.net/19591/ ）。

## 4. 段組みの基本型と TOML の書き方

### 4.1 フィールド

| フィールド | 置き場所 | 意味 |
|---|---|---|
| `tiers` | ページ | 段の高さの比。`[0.4, 0.35, 0.25]` なら上から 40%・35%・25%。省略すると等分 |
| `tier` | コマ | 何段目か（0 が最上段） |
| `width` | コマ | 段の中での幅の比。同じ段のコマは**書いた順に右から左へ**並ぶ |
| `column` | コマ | 同じ段で同じ `column` の値を持つコマは、縦に積む（列の幅は最初のコマの `width`） |
| `height` | コマ | `column` の中での高さの比（縦読みでは、幅に対する高さの比） |
| `bbox` | コマ | ページ全体を 0〜1000 にした `[x1, y1, x2, y2]`。変形や斜めの近似、はめ込みに使う。書くと `tier` より優先 |
| `bleed` | コマ | タチキリ。`true`（基本枠に接する全辺）か `"top,left"` のような辺の指定 |
| `inset` | コマ | 他のコマに重ねてはめ込む。これが無い重なりは P10 |
| `order` | ページ | `"written"` で、書いた順を読む順にする（はめ込みを先に読ませる型など。書き出しもこの順） |
| `splash` | ページ | 1 枚絵・扉など、コマ数の目安から外れてよいページ |
| `spread` | ページ | 見開きの始まり（右ページに置く） |
| `turn` | ページ | 左ページで「最終コマで何を引き、めくった右ページの 1 コマ目で何を見せるか」 |
| `gap` | コマ | 縦読みで、そのコマの前に取る余白（幅に対する比。既定 0.25） |

### 4.2 基本型（右→左の番号つき）

**型 A: 3 段・5 コマ（通常の展開）**

```
tiers = [0.33, 0.34, 0.33]
┌──────────┬──────────────┐
│    2     │      1       │  tier 0: 1 (width 0.6), 2 (width 0.4)
├──────────┴───┬──────────┤
│      4       │    3     │  tier 1: 3 (0.4), 4 (0.6)  ← 縦の境目を 1 段目とずらす
├──────────────┴──────────┤
│            5            │  tier 2: 5
└─────────────────────────┘
```

**型 B: 大ゴマ 1 ＋小ゴマ（感情を見せる。大 1 コマ約 60%＋小 2〜3 コマという実践談: https://note.com/note_ai_s/n/n4907130c077d ）**

```
tiers = [0.25, 0.75]
┌────────┬────────┬───────┐
│   3    │   2    │   1   │  tier 0: 小ゴマ 3 つ（溜め）
├────────┴────────┴───────┤
│                         │
│            4            │  tier 1: 大ゴマ（見せ）
│                         │
└─────────────────────────┘
```

**型 C: 縦に割った組（右に 2 コマ、左に縦長 1）**

```
┌──────────┬──────────────┐
│          │      1       │  1: tier 0, column 1, width 0.6
│    3     ├──────────────┤
│          │      2       │  2: tier 0, column 1
├──────────┴──────────────┤  3: tier 0, width 0.4
│            4            │  4: tier 1
└─────────────────────────┘
```

```toml
[[pages]]
tiers = [0.65, 0.35]
  [[pages.panels]]   # 1
  tier = 0
  column = 1
  width = 0.6
  [[pages.panels]]   # 2
  tier = 0
  column = 1
  [[pages.panels]]   # 3（縦長: 高さ・落下・全身）
  tier = 0
  width = 0.4
  [[pages.panels]]   # 4
  tier = 1
```

**型 D: 均等 2 段・4 コマ（会話の往復、日常）。** 単調さが欲しいとき（めくりの直前、5 節）にも使う。全ページをこれにしない。

**型 E: 1 段 1 コマ（扉・見せ場）。** `splash = true`。

`manga_name.py` の配置は叩き台で、絵の出来ではない。人物や吹き出しの位置を固定したいときは、その項目に `box = [x1, y1, x2, y2]`（コマの中の 0〜1）を書く。

## 5. めくり

紙の本では、読者は見開き 2 ページを同時に見て、左ページを読み終えたらめくる。めくった瞬間に右ページの 1 コマ目が目に入る。だから:

- **左ページの最終コマ＝引き**（次が気になる問い、言いかけの台詞、振り向く直前、扉を開ける手）
- **めくった右ページの 1 コマ目＝見せ**（正体、答え、表情、大ゴマ）

という役割に固定する。資料によって「メクリ」「ヒキ」の呼び方が逆なので、このスキルではこの定義で呼ぶ（`docs/dev/research-2-manga-craft.md`）。

- **見せたいコマを、同じ見開きに置かない。** 見開きの中に答えがあると、読者は問いを読む前に答えを見てしまう（https://takagi-shinry.com/2017/07/16/how-to-make-manga-layout-mekuri-hiki/ 、目安）。
- **めくりの直前のページは、あえて均等で単調な割りにする。** めくった後の大ゴマで落差を作る（大今良時、https://www.clipstudio.net/oekaki/archives/152311 ）。
- **スマホで 1 ページずつ読まれる媒体では、引きを毎ページに置く**（同上の takagi-shinry、目安）。

**ページの左右**: `manga.toml` の `first_page_side`（既定 `left`）で決まる。既定では奇数ページが左、偶数ページが右で、見開きは（2, 3）（4, 5）…になる。1 ページ目は左ページ単独（向かいは表紙や前の作品）。扉を右に置く媒体なら `right` にする。

- 左ページの `turn` が空で、そのあとにページが続くと、`name_lint.py` が **P07**（INFO）を出す。めくりの設計を書き込む合図で、必ず埋めろという命令ではない。ただしめくりの位置を意識せずにネームを切るのは、LLM のネームの典型的な抜けである。
- 1 ページ目の左上（右綴じで 1 ページ目が左ページなら右上）のコマが特に重要という編集部の指摘がある（https://www.cmoa.jp/cmoacomics/pickup/post-51-9.html ）。

## 6. 見開き

- **クライマックスで使う。** 2 ページ全体を 1 枚にする方法と、上段だけを見開きにする方法がある（https://shincomi.shogakukan.co.jp/training/005.html ）。
- **見開きは右ページから始める。** 左ページから始めると 2 ページが同じ紙の表と裏になり、見開きにならない。`spread = true` を左ページに書くと **P08**。
- 見開きの直前の左ページで引き、めくった瞬間に見開きが開くのが最も強い。見開きの位置は `plot/structure.md` の「見開き・扉の位置」に先に書く。
- 見開きの中の台詞はノド（綴じ目）にかけない。

```
      左ページ（奇数）        右ページ（偶数）
┌────────────────────────┬────────────────────────┐
│                                                 │
│         見開きの大ゴマ（spread = true は右ページに）  │
│                                                 │
└────────────────────────┴────────────────────────┘
```

## 7. タチキリ・変形ゴマ・枠なし・はめ込み

- **タチキリ（裁ち切り）**: コマを紙の端まで伸ばす。多用しても読みにくくなりにくい（https://shincomi.shogakukan.co.jp/training/005.html ）。広さ、開放感、迫力。
  - **ノド側（綴じる側）へのタチキリは避ける。** 綴じに絵が食われる。右ページのノドは左の辺、左ページのノドは右の辺。`bleed` がノドの辺を含むと **P12**。見開き（`spread`）は例外。
  - **台詞は基本枠（内枠）の内側に置く。** 裁ち落とされる。B4 投稿原稿の基本枠は 180×270mm（https://www.hamano-manga-club.com/skill-box/skill/manuscript-paper/ ）。ネーム画像（`name_render.py`）の水色の破線が基本枠。
- **変形ゴマ・斜めゴマ**: 「ここぞ」に限る（https://shincomi.shogakukan.co.jp/training/005.html ）。アクションの衝撃、感情の動揺。毎ページ使うと効かなくなる。TOML では `bbox` で近似し、`note` に「斜め」と書く（配置計算は長方形だけ）。
- **枠なしのコマ**: 人物を枠の外に出す、余白に浮かべる。回想、夢、心の声、時間の止まった瞬間。`bbox` で置き、`background = "white"`。
- **はめ込み（inset）**: 大ゴマの中に小さなコマを重ねる。大ゴマの情景の中で、手元や表情を同時に見せる。`inset = true` を小さいほうに書く。書かずに重ねると **P10**。

## 8. 間（ま）の作り方

漫画の「間」は、文字の無い時間を紙の上に作ることだ。LLM のネームは、全コマに台詞を入れて間を潰しやすい（`docs/dev/research-1-ai-manga-pipeline.md` の実践談）。

- **無言のコマを 1 つ置く。** 告白の返事の前、驚きの直後、別れの後。台詞の無いコマは、読者が自分で間を読む時間になる。
- **同じ構図を繰り返す。** 同じ `shot`・`angle` で、ほんの少しだけ違う（表情、手、背景の時計）コマを 2〜3 つ並べる。`transition = "moment"`。読者は「動かない時間」を感じる。意図した反復は P04（同じショットの連続）が出ても keep。
- **長い台詞を 2 つの吹き出しに分け、後ろを下にずらす**と間が生まれる（青山剛昌、https://mannavi.net/19591/ ）。
- **空白・横長のコマ。** 情景だけの横長のコマ（`shot = "extreme_long"` か `"long"`、人物なし）。場面の余韻、時間の経過。
- **縦読みでは余白そのものが間。** コマとコマの空白の大きさで場面転換や心理を表す（https://www.clipstudio.net/oekaki/archives/156251 ）。TOML の `gap` を大きく取る（11 節）。

## 9. 1 ページ目と冒頭 6 ページ

- 冒頭 6 ページまでに魅力が無いと読者が離れる（大今良時、https://www.clipstudio.net/oekaki/archives/152311 ）。
- 1 ページ目に置くもの: 誰の話か（主人公の顔か、印象的な姿）、どこの話か（場所が分かる引き）、何が起きそうか（違和感、問い）。三つを 1 コマに詰めず、2〜4 コマに分ける。
- 冒頭の場所を見せる。作品の冒頭と、場所や時間が変わるときは背景を描く（https://manga-biz.com/column/webtoon_2/ 、目安）。場面の頭のコマに `place` が無いと **P03**、場面の最初の 3 コマに引き（long・full・extreme_long）が無いと **P11**（INFO。場所を伏せる意図なら keep）。
- 1 話の中で主人公の感情が変わるかが最重視される（https://www.cmoa.jp/cmoacomics/pickup/post-51-9.html ）。冒頭のページで「最初の感情」を見せておく。

## 10. 4コマ

- **各コマは同じ形で均一に並べ、起承転結に割り振る**（https://comic.smiles55.jp/guide/20130/ ）。
  - 1 コマ目（起）: 舞台と人物の紹介
  - 2 コマ目（承）: 事件が起きて話が進む
  - 3 コマ目（転）: 山場。ずらし、予想の裏切り
  - 4 コマ目（結）: オチ
- TOML は `format = "yonkoma"`。`tiers` を書かなければ、4 コマを縦一列に等分する。1 ページに 8 コマ書くと 2 本並び（右の列が 1 本目、左の列が 2 本目）に配置する。**2 本並びを右の列から読むという規定は明文化された資料を確認できていない**（未確認）。縦書きの読み順からの慣習として扱う。
- 1 ページのコマ数が 4 の倍数でないと **E09**（FAIL）。
- 4 コマのコマは小さく横長なので、1 コマの吹き出しは 1〜2 個、1 行は短く（`thresholds.json` の yonkoma: 1 行 10 字、1 コマ 2 個が目安）。
- オチのコマは、台詞で説明しない。無言の絵、ひとことの台詞、欄外の小文字（`type = "aside"`）のどれかで落とす。3 コマ目で落ちが見えると 4 コマ目が死ぬので、3 コマ目は「転」の手前で止める。
- 役割は `role = "起"` のようにコマに書いておくと、自分で確かめやすい（読者用の台本には出ない）。

## 11. 縦読み（webtoon）

- 1 話の分量: comico 編集部は 50〜60 コマ、決めゴマ 1〜3、紙換算で約 10 ページ（https://note.com/comico_jp/n/nbfcfacb6a916 ）。マンガラボは第 1 話 100 コマ以上、2 話以降 60〜80、1 画面 1〜3 コマ（https://info.manga-lab.net/?p=2765 ）。
- 投稿サイズ: LINE マンガインディーズは推奨横 800px、comico チャレンジは横 690px・縦 20,000px まで（https://www.clipstudio.net/oekaki/archives/156251 ）。制作は投稿サイズの 2 倍で描く（manga-lab）。最新の規定は投稿先で確かめる（`formats.md`）。
- **1 フキダシ 3〜4 行まで**（https://info.manga-lab.net/?p=2765 、https://mannavi.net/21297/ ）。横に並べず、上から下へずらす。
- 画面の中央 1/3 にコマかフキダシを置く方法がある（https://confidence-creator.jp/column/24210/ 、目安）。
- **余白が時間。** 短い余白は連続した動作、長い余白は場面転換・沈黙・時間経過。引きの直前は長い余白で溜める（`paneling-patterns.md` の 33）。
- 紙の文法（めくり、見開き、段の右→左）を持ち込まない。縦読みは 1 画面ずつ、上から下へ進む。

TOML: `format = "webtoon"`。1 つの `[[pages]]` が 1 区切り（ひと続きにスクロールする範囲）。コマは書いた順に縦に積まれる。

```toml
[[pages]]
number = 1
  [[pages.panels]]
  height = 1.2      # 幅に対する高さ（縦長）
  [[pages.panels]]
  gap = 0.15        # 短い余白: 続きの動作
  height = 0.6
  [[pages.panels]]
  gap = 1.5         # 長い余白: 溜め
  height = 1.4
```

`bleed` は縦読みでは既定で横幅いっぱい。左右に余白を取るコマは `bleed = false`。

## 12. TOML のフィールドと lint の対応表

| コード | 何を見るか | 直し方 |
|---|---|---|
| P01 | 1 ページのコマ数が目安（既定 3〜8）の外 | 割り直す。意図した 1 枚絵なら `splash = true` |
| P02 | 書いた順と、配置から計算した読み順が違う | 配置か、書く順を直す。縦の境目が段ごとにそろっていないか確かめる |
| P03 | 場面の頭のコマに `place` が無い | 場所を決めて書く |
| P04 | 同じ `shot` が続く | 寄りと引きを入れ替える。意図した反復（間）なら keep |
| P05 | 顔の寄りと台詞だけのコマが続く | 引きに戻す、動作（`action`）を入れる、背景を描く |
| P07 | 左ページの `turn` が空（INFO） | めくりの引きと見せを書く |
| P08 | `spread` が右ページから始まっていない | ページ数か `first_page_side` を見直す |
| P10 | コマが重なっている | 重ねる意図なら `inset = true`、そうでなければ配置を直す |
| P11 | 場面の最初の 3 コマに引きが無い（INFO） | 場所を伏せる意図なら keep |
| P12 | ノド側へのタチキリ | ノド以外の辺に。見開きなら `spread` |

lint は「確かめる箇所」を示すだけで、修正命令ではない。意図した選択なら本文を変えず、keep の理由を一句残す（SKILL.md「lint の読み方」）。
