# P-H3 image ネイティブ化計画の敵対的レビュー（gpt-6.2-astra、OpenAI API 経由）

1. **【高】手順2・3：重みの dtype では実行カーネルを決められない。**  
   **失敗：** H3 のテキストエンコーダーは、同じ int8 convrot 保存でも活性は FP32 だった。DiT の bias なし qkv が1本一致しても、テキスト側の計算精度や VAE の bias 加算後の丸めまでは保証しない。  
   **最小修正：** 手順1で DiT・テキスト・VAE 各々の実呼び出し、入出力 dtype、scale・回転・bias の適用順を採る。対象 GPU の実形状で通る経路だけを取り込み、「可能なら融合」は削る。

2. **【致命】手順4：`text_connector` の出口は DiT の入口ではない。**  
   **失敗：** connector の出力は幅 5120、`dit_forward` が `audio_embed`・`video_embed` と連結する `context` は幅 5376。connector までビット一致しても、そのまま渡すと最初の `cat` で止まる。  
   **最小修正：** 画像版の条件投影・refiner を既存の `condition.cpp` に通し、手順4の照合終点を **DiT 呼び出し直前の `context` と `token_tags`** にする。`te.cpp` は4B実重みの Q/KV 形状と5層の取得位置に合わせ、汎用化は削る。

3. **【高】手順5：`latent_shapes(..., length=1)` は画像用の形を返さない。**  
   **失敗：** `frame_count(1)` は5なので、映像は `T=2`、音声は末尾長8になる。正解はそれぞれ1と2。映像 noise の乱数消費量が変わるため、後から切り詰めても同じ seed の音声 noise には戻らない。  
   **最小修正：** 画像の2形状を直接 `initial_noise` に渡し、BF16 化前の FP32 noise を基準と照合する。手動 sigma 9値、全8回 Euler、shift 1/1、`audio_scale=1`、SLA 統計なしに固定し、動画の `sample()` は経由しない。

4. **【高】手順3・7：2912角の dense attention は、1024角で通っても既定サイズで止まり得る。**  
   **失敗：** SDPA がスコア行列を実体化する経路に落ちると、映像だけで `56 × 8281²` 要素、FP32 なら約14 GiB。21 GB の DiT 重みとは別に必要で、既定サイズだけ OOM または大幅に遅くなる。  
   **最小修正：** 手順1の2912角で ComfyUI が実際に選んだ attention バックエンドを確認し、native も同じ経路で1 forward を通す。速度比較はテンソル保存を外し、同じ GPU 占有条件・ウォーム状態で行う。

5. **【高】手順6：`ph3_image_pixels` の戻り値は完成画像ではない。**  
   **失敗：** この関数は `post_quant_conv` から始まり、正規化空間の画素で終わる。直接保存すれば色がずれる。また2912角を一括投入すると、VAE は DiT の8,281ではなく `182² = 33,124` パッチを処理する。  
   **最小修正：** 画像版の実経路で latent 逆正規化、タイル範囲・バッチ数、画素の逆正規化を確定し、該当する既存関数だけをつなぐ。照合は同じ最終 latent から保存直前の RGB まで。動画の時間チャンク処理は使わない。

6. **【高】手順8：編集の参照画像は、vision 塔と VAE の入口を別々に合わせる。**  
   **失敗：** Lanczos という名前だけ合わせても、非正方形画像の寸法丸めが片方で違えば、vision のパッチ列と画像トークン数が食い違うか、VAE の参照 latent が別の画素配置を表す。T2I では発見できない。  
   **最小修正：** 予定済みの編集1件を非正方形の参照にし、vision 側の入力・グリッド・画像トークン位置と、VAE 側の入力画素・参照 latent を同じ実行から採る。両者の前処理を共通化しない。

7. **【致命】手順8：`minimax_refs` は入力を詰めるだけでは実装できない。**  
   **失敗：** 現行 `dit_forward` には参照引数がなく、`head(v0, layout.seq, ...)` は末尾まで生成対象として reshape する。参照行を末尾に足すだけなら、RoPE・AdaLN の割当てが違ううえ、出力の行数も合わない。  
   **最小修正：** 参照1枚に限って、実グラフの並び・位置・時刻行を既存 forward に反映し、生成対象の行だけを出力ヘッドに渡す。旧経路の削除は、ComfyUI を起動せず編集画像まで出た後にする。

**手順9の推奨：a（移植しない）。**  
9.7 GB の重みをロードせず、最大2048トークン（編集3072）の逐次生成も丸ごと省ける。  
既存ワークフローの拡張 off と同じ条件で出せるので、b の GGUF 変換・サーバー起動も、c の専用実装も不要。

**判定：修正後に着手可。**
