# Anima ネイティブ生成計画の敵対的レビュー（gpt-6.2-astra、dsh ask openai 経由）

1. **［高］「約7秒」と比較する計測と、正しさを調べる採取は分ける。**  
   **失敗:** H3 の `capture_reference.py:28–71` はテンソルを CPU にコピーし、tokenizer と DiT のフックも MiniMax 専用。そのままでは Anima の内部値は採れず、コピー込みの時間も速度基準にならない。逆に同じ入力を再実行すると、ComfyUI のノードキャッシュで生成処理まで省かれ得る。  
   **最小修正:** 採取は Anima のフックに差し替えた1件だけ。速度はフックなし・モデル常駐・異なる固定 seed 3個で、両者とも同じ範囲の「開始→画像保存」の中央値を測る。7秒なら、DiT に使える時間は **1 step 約206 ms 未満**で、実際にはここから条件生成・VAE・保存時間を引く。

2. **［高］`conditioner.pt` はプロンプトの意味まで互換ではない。**  
   **失敗:** 学習側は文字列をそのまま tokenize して両系列を512で切る。一方 ComfyUI は `(red:1.5)` の構文を解釈し、Qwen 側の重みは1、T5 側の重みは **adapter の出力行に**掛ける。512は上限ではなく、短い出力をゼロ埋めする最小長。普通の短文1件が合っても、強調・長文・空ネガティブの確認にはならない（`export_frontend.py:70–83,127–131`、`comfy/text_encoders/anima.py:8–27`、`comfy/ldm/anima/model.py:198–206`）。  
   **最小修正:** 正負それぞれで **Qwen ID・T5 ID/重み → 実際に DiT が受け取る `c_crossattn`** を照合する。短い強調付き正条件と空の負条件を使い、初版で512超を扱わないなら黙って切らない。adapter は各条件につき生成前に1回だけ動かす。

3. **［高］現行 `predict()` の「ビット一致」は、DiT を省検証で流用する根拠にならない。**  
   **失敗:** `docs/anima-native-benchmarks.md:144–156` は、融合後は diffusion-pipe ともビット一致しないと明記している。さらに ComfyUI の自己注意は `rms_rope_split_half`、ネイティブは RMSNorm と RoPE が別演算。残差更新も ComfyUI の `addcmul` に対しネイティブは乗算してから加算する。最終画像だけを見て差を sampler のせいにすると、直す場所を誤る。  
   **最小修正:** 同じ latent・実 timestep・条件を注入し、**先頭ブロックの回転後 Q/K と残差 → 1 forward の正負の速度予測**の順で比べる。差が問題になる場合だけ既存の split-half 融合実装を使う。全層のビット一致も、既存の融合カーネルの作り直しも不要。

4. **［致命］`er_sde` は「shift 3・同じ seed」だけでは再現できない。**  
   **失敗:** `simple` は等間隔の34点を直接作るのではなく、1000個の表から切り捨て添字で選び、末尾に0を足す。さらに ER-SDE は FLOW の先頭 σ=1 を補正してから `λ=σ/(1−σ)` を使う。補正を落とせば初回が特異点になる。Anima の timestep 倍率は **1** で、solver が受けるのは生の DiT 速度ではなく `x−σv` から作った CFG denoised。初期 noise は CPU FP32、途中の noise は latent と同じデバイスの別 generator であり、同一 seed の CUDA 乱数列1本では一致しない。  
   **最小修正:** `samplers.py:645–652` と `k_diffusion/sampling.py:1593–1656` を仕様にし、35個の σ、補正後の先頭値、途中 noise を採る。参照値を注入して第1・第2・第3更新（履歴と200点積分）と終端の `x=denoised` を照合してから、seed 起点で確認する。全34回の cond/uncond ダンプは削る。

5. **［高］CFG の batch 2 固定は、速度にも出力にも不利になり得る。**  
   **失敗:** 832×1216 は画像側だけで3,952 patch。B=2 にしても正負2本分の演算は残り、現行 `modulated_norm` は B>1 でサンプル別に FP32 LayerNorm を呼んで `stack` する（`native/model.cpp:187–205`）。また正負の条件長が異なるとき、追加のゼロ埋めでまとめても同じ結果にはならない。cross-attention にその埋め草を除くマスクがないため。  
   **最小修正:** 実寸・同じ条件で **B=2 対 B=1×2** の正負出力と合計時間を比較し、速い方だけ使う。条件長が異なる場合は別 forward にし、CFG=1 なら負条件の forward 自体を省く。

6. **［高］VAE の逆正規化は、どの latent を受け取るかで一回分ずれる。**  
   **失敗:** ComfyUI の **KSampler 出力はすでに** `process_latent_out(samples.float())` 済み。これを「最終 latent」として、逆正規化を含む予定の TorchScript に直接入れると、16チャンネルの `z×std+mean` が二重に掛かる。正しいデコーダーでも色やコントラストが壊れる（`comfy/samplers.py:1239`、`latent_formats.py:774–777`）。  
   **最小修正:** solver 終端と KSampler 出口を区別して保存する。前者から FP32 で一度だけ逆正規化し、後者と照合してから、`qwen_image_vae` の `conv2 → decoder`、`[0,1]` 変換後の保存前 RGB を比べる。生成には VAE エンコーダーも動画用デコードも要らない。

7. **［高］LoRA の目視確認だけでは、無適用・二重適用・前回分の残留を見逃す。**  
   **失敗:** 実ファイルでは `darask-anima-native-style` は448組、`darask-anima-native-mlp` は56組の A/B で、どちらにも alpha テンソルはない。同じ `trained/` には H3・Qwen 用もある。全ファイルを選択可能にして未一致キーを無視すると「成功した素の画像」が出る。常駐中のマージ済み重みに次の LoRA を足すと、今度は前回分が残る。  
   **最小修正:** 選んだ Anima LoRA の全 A/B 組が対応することを確認し、alpha なしを余分に rank で割らず、未変更の base から参照経路と同じ BF16 演算で一度だけマージする。`predict()` には空の adapters を渡し、同じ入力で **なし→あり→なし** の予測を比べる。

8. **［中］速度改善を UI の後に置き、Graphs・融合・FP8 を順に試すのは遠回り。**  
   **失敗:** RMSNorm・RoPE・LayerNorm 変調はすでに採用済み。1024px の既存計測は**学習**なので推論速度の証明ではないが、FP8 の forward 単体でも活性変換込みの MLP2 は BF16 **0.474 ms → FP8 0.487 ms** と遅い。一方、現行 `predict()` が34回作り直す画像 RoPE 表と、各ブロックが34回投影し直す不変の text K/V は計画の候補から漏れている。  
   **最小修正:** BF16 で1枚保存できた時点で、パネルより先に実寸の内訳を測る。不変計算が効けばその生成内で一度にし、Graphs は GPU の空き時間がある場合だけ、FP8 は変換込みの総秒数で勝つ投影だけ。目標を超えたらそこで止め、初版からチャットツールを外す。

**判定：要修正。基準採取からは着手可。**
